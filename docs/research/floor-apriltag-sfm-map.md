# 床 AprilTag SfM マップ方式による多カメラ extrinsic キャリブ (共視不要)

> Status: **モード(a) 既知配置 PnP は実装済み** (2026-06-15) —
> [design/pose-3d-floor-apriltag-extrinsic.md](../design/pose-3d-floor-apriltag-extrinsic.md) に昇格。
> 本 research ノートは **(b) スマホ SfM 自動復元** (本命方向・未実装) の検討記録として残す。
> モード(a) はマップを実測で与え、(b) は同じ `FloorTagMap` を SfM で生成するだけ — localize コア
> (`floor_extrinsic_solver`) は共有。下記「実測知見」は (a)(b) 共通の検出条件。
> 上流 = controller-marker 案C ([design/pose-3d-controller-marker-extrinsic.md](../design/pose-3d-controller-marker-extrinsic.md)) の **代替選択肢**。

## 背景 / 動機

案C は VR コントローラ固定 AprilTag を共通アンカーにした hand-eye (`AX=ZB`) で各カメラの
`T_cam←world` を解く。距離問題を「近接」で解き共視不要を実現したが、代償として **Quest 3 の
SLAM 原点ドリフトが inter-camera extrinsic に直接乗る** (誤差バジェットの律速。Quest 公表値なし、
M0 で実測予定)。

ここで検討するのは「**静的な物理アンカーを共通 frame にし、VR を extrinsic チェーンから外す**」
別経路。狙いは 2 つ:

- VR を起動しない / Quest を持たない環境でも extrinsic を取れる経路を用意する。
- 律速だった SLAM drift 項を誤差バジェットから消し、**再現性で案C を上回る**余地を作る。

## 手法概要

**静的フィデューシャルマップ + 各カメラ個別 localize。** 床と周囲に AprilTag を配置して 1 つの
3D マーカーマップ (= 共通 world frame) を作り、各固定カメラはそのマップに対して個別に PnP で
localize する。

**共視不要の肝**: 各カメラは「相手カメラ」ではなく「**共通マップ**」に登録される。1 枚しか
タグが見えないカメラでも、マップが「タグ間の相対配置」を知っていれば world に載る。カメラ同士が
同一フレームを共有する必要がない。

これは案A/案B の**復活形だが却下理由を迂回する**:

- 案A 却下理由「1.2m で全カメラ同時共視が不能」→ **マップ構築 (オフライン・スマホ) と各カメラの
  localize を時間分離**するので「同時性」が要件から消える。
- 案B 却下理由「BA は共視経路が前提、本環境では成立しない」→ **静的マップそのものが共視経路の
  代替** (マップが各カメラを間接的に繋ぐ)。

## 構成要素

- **床の大判 AprilTag** — 36h11 を A4 (≒21×29.7cm) 程度で複数枚。大サイズは遠距離デコードに効き、
  既存 `cpp/src/lift/apriltag_marker.cpp` (36h11 PnP) をそのまま流用できる。ID 付き視点不変コーナー
  対応なので裸テープ texture と違いクロス視点でも確実に対応が取れる。
- **面外拘束用の可搬スタンド** (壁は不要) — 三脚 + プラダン/フォームボード/クリップボード、譜面台、
  自作の三角柱/L字ターゲットなど。床と非平行な面にタグを貼れれば何でもよい。複数の高さ・向きを
  作れると平面縮退対策に効く。

## 配置モード (2 通り)

- **(a) 既知配置 = 実測して貼る** — タグ間隔を測って配置を確定。各カメラは見えたタグの既知 3D
  コーナーに直接 PnP すればよく、**SfM もスマホも不要**でスケールもタダ。最も堅く速い。手間は
  設置時の実測。
- **(b) スマホ SfM 自動復元 (本命方向)** — タグを適当に貼り、スマホ全景撮影で配置を自動復元。
  **タグ物理サイズが定規になりスケールも自動**。条件 2 つ:
  - **隣接タグがオーバーラップして 1 フレームに複数枚写る撮影**が必須 (でないとタグ間相対姿勢が
    繋がらずマップが分裂する)。
  - **床タグと面外スタンドのタグが同一フレームに写るフレーム**を作る (両者を 1 つのマップに融合)。

## 精度の要点

- **平面縮退が最大の罠** — 全タグを床 (同一平面) に寝かせると、平面を斜めから見る高所カメラの
  height/tilt 推定が悪条件になる。→ 面外スタンドのタグで法線方向を増やすと緩和。各カメラが複数枚
  同時視できれば単タグ依存も避けられ縮退がさらに緩む。
- **クロス視点マッチング** — スマホ (ほぼ真上) と固定カメラ (浅角) の視点差は大きいが、AprilTag の
  ID 付き視点不変コーナー対応で吸収できる。裸テープ純 SfM (SIFT/ORB) はここで崩れるため非推奨。
- **スケール cross-check** — モード(b)でもスケールはタグサイズで付くが、2-3 点の実測距離を 1 本
  入れておくと独立な cross-check になり、SfM のスケールドリフト検出に使える (安価な保険)。

## 運用

- **1 セッション中 (スマホ撮影 → 全固定カメラ収集が終わるまで) スタンドを動かさない・蹴らない。**
  床タグとスタンドタグが 1 つのマップに融合されるので、途中でずれるとマップが壊れる。
- スマホ撮影で **床タグとスタンドタグが同時に写るフレーム**を必ず作る (繋がないとスタンドが別マップに
  浮く)。
- 完了後はスタンドを撤去してよい (常時プレイエリアを占有しない。据置のカラーボックス等は不要)。

## 実測知見 (2026-06-13): 検出可否とサイズ閾値

実機 2 カメラで床配置 36h11 タグの検出可否を実測。本案の前提「固定カメラが床タグを安定検出できるか」
を確認した最初の実験。検証スクリプト: `python/scripts/detect_apriltags.py` (CLAHE / fourcc / 解像度
切替, 検出 ID 集計, 注釈画像保存)。確認画像: `outputs/apriltag_check/`。

**環境**: cam0=`usb-0:2.3`, cam1=`usb-0:2.4` (ELP AR0234, 強い魚眼)。MJPG **1280×960** (4:3 = VGA と
同一画角・2 倍解像度) を既定とした (タグが小さく写るため解像度は欲しいが、画角は VGA 相当を維持)。

### 1. 検出律速は「歪み」でも「JPEG」でもなく「軟調/局所コントラスト不足」

当初 cam1 が遠景タグを取りこぼした。切り分けの結果:

- 同一フレームで前処理比較: raw `[6,9]` → unsharp `[6,7,8,9,11]` → **CLAHE `[6,7,8,9,10,11]` (全6個復活)**。
- YUYV (非圧縮) でも改善せず → **JPEG 圧縮は主因でない**。
- 魚眼で湾曲した周辺タグも CLAHE で復活 → **歪みも検出の主因でない** (歪みは*メトリック姿勢*には効くが*検出*には効かない)。
- 原因はレンズの軟さ (固定/手動焦点) による低コントラスト。**→ 検出フロントエンドに CLAHE
  (`createCLAHE(2.0,(8,8))`) を常用すべき。** これだけで両カメラ全タグが安定検出になった。

### 2. 検出可否を決める支配変数 = 「弱い側カメラでの投影 edge_px」

3 回の配置替え (近め全14 / 遠め / 大小混在) を通して一貫した閾値:

| 弱い側カメラの edge_px | 検出安定性 |
|---|---|
| **≥ 約 30px** | 両カメラ 30/30 で盤石 |
| 約 25〜30px | 弱い側でバラつく (数〜半分のフレーム) |
| < 約 25px | 頻繁にロスト |

- 「両カメラとも ≥30px」のタグだけが安定共視できる。片側が <30px に落ちた瞬間に脱落。例外なく
  この線で説明できた (大タグでも遠ざかって片側 ~28px になると脱落)。
- **限界は物理サイズではなく投影 edge_px で決まる。** 設計指標 = 「最悪条件のカメラから edge ≥ 35px
  (安全マージン)、最低 30px」。

### 3. スケール則 (大タグ = 168mm 実測)

- 168mm タグは現配置で edge ≈ 40〜46px (cam0) / 38〜44px (cam1)。30px フロアに対し**見かけ余裕 ≈ 1.33×**
  (現位置からさらに ~30% 遠ざけると脱落圏)。
- `edge_px ∝ タグ実寸 / 距離` (線形)。→ **検出最大距離 ∝ タグ実寸**。168mm タグは 110mm タグの約 1.5 倍
  遠くまで届く。床全域カバーは「**遠い位置=大タグ / 近い位置=小タグ**」の使い分けが正解。
- **絶対距離 (m) は未確定** — `Z ≈ f_px × 実寸 / edge_px` の f_px が未知 (かつ魚眼) のため。粗い FOV 仮定
  では id13(43.5px) で Z ≈ 1.4〜2.5m (HFOV 90〜120° 幅)。確定には intrinsic 校正 (`calibrate_intrinsics_charuco.py`)
  か大タグ 1 枚の実距離実測 1 点が要る。

### 本案への含意

- 検出フロント = MJPG 1280×960 + CLAHE で確定。固定カメラ側の床タグ検出は実現性◎。
- 「適当・大小ごちゃまぜ配置でも検出は成立」だが、extrinsic 精度には **広く散らす (幾何○)** と
  **edge≥30px 維持 (検出○)** の両立が条件。遠くに置くほどタグを大きく。
- 次工程は intrinsic 魚眼校正 → 既知配置(a)/SfM(b) で extrinsic + 再投影誤差。本実測はその手前の
  「検出が成立する配置・サイズ条件」を数値化した段階。

## 案C との比較

| 観点 | 案C (controller-marker) | 本案 (床 AprilTag SfM マップ) |
|---|---|---|
| カメラ間共視 | 不要 (VR world で連結) | 不要 (共通マップで連結) |
| 共通 frame の正体 | VR world (動的) | 静的物理マーカーマップ |
| SLAM drift 依存 | **あり (律速)** | なし |
| VR / Quest 依存 | 必要 | 不要 |
| 据置物 | なし (コントローラ持ち回り) | セッション中だけ可搬スタンド |
| 向く場面 | VR 運用前提・素早い再キャリブ | VR 非起動・高再現性・ドリフト実測 |

## 未解決 / 次の論点

- **SfM ツール選定** — COLMAP (汎用 SfM・特徴点ベース) か、AprilTag コーナー対応に特化した軽量自前
  BA (`apriltag_marker` のコーナー出力 → タグ間相対姿勢を最適化) か。後者は床マップ用途に素直で
  依存も軽い。モード(a) 既知配置なら SfM 自体が不要。
- **M0 グラウンドトゥルースとしての活用** — 本案で静的マップから「正解 extrinsic」を出し、案C が
  乗せている未知の Quest SLAM drift 量を**実測する独立リファレンス**にできる。案C を主軸に残しても
  検証価値が高い。
- intrinsic は既存 `python/scripts/calibrate_intrinsics_charuco.py` (ChArUco 近接) を流用。
- 初期設定 UI で案C / 本案を選択させる導線 (収集フローの分岐) の設計。
