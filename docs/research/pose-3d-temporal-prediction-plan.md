# pose-3d: 3D平滑化・1〜2レポート先予測 AI の検討

更新日: 2026-09-08。状態: **RTMPose-M選定済み、評価器M1／学習モデルは未着手**。
追跡Issue: [#65](https://github.com/1hira-c/fitra-cam/issues/65)。
先行作業: [姿勢推定モデル・オーディション](pose-model-audition-plan.md)。

## 目的と着手条件

姿勢推定モデルを選定した後、その出力を3D化した関節系列に対して、平滑化と直近未来の
予測を行う軽量な時系列モデルを検討する。静止時の揺れと動作中の追従遅れを抑えつつ、
推論の処理遅延は極限まで削る。対象は既に3D化された系列であり、2D遮蔽の解決や
長時間の欠損補完を主目標にしない。

先に姿勢推定モデル・topology・運用条件を決め、その実際の出力傾向を入力データへ
反映する。2026-09-08にRTMPose-M続行を決定。学習・既定filter置換に先立ち、
[後段の固定リプレイ評価器](../design/pose-3d-temporal-evaluation.md)を実装する。
両時間filter OFFは遅延十分許容、Kalmanのみも一応許容という実機フィードバックを基準に、
体感に頼りきらず比較できるか検証する。学習モデルや本番のfilter置換はまだ行わない。
後段モデルの完成を姿勢推定モデル選定の開始条件にしない。

## 合意した方針

| 項目 | 初期方針 |
|---|---|
| 入力 | 現在までに届いた3D関節のレポート系列 |
| 出力 | 平滑化と、1〜2レポート先の短期予測 |
| 実時間処理 | 現在の入力が届いたら処理し、未来の実測レポートを待たない |
| 教師生成 | 大型モデルと十分な過去・未来情報を使うオフライン補正 |
| 時間の扱い | ほぼ一定周期のレポート単位から始め、厳密なフレーム間隔入力は必須にしない |
| 許容範囲 | 短い予測区間での一時的な外れを許容し、完全無誤差を目指して待ち時間を増やさない |

60Hzでレポートが届く場合、1ステップは約16.7ms、2ステップは約33.3ms相当となる。
これは**予測の時間幅**であり、推論に使ってよい処理時間や、意図的に追加する遅延ではない。
カメラcapture fpsと3Dレポートの更新周期は区別する。

## 教師生成と推論の分離

人手で全フレームを注釈することは前提にしない。元映像を大型モデルで処理し、3D化後に
前後の情報を十分使って補正した軌跡を、信頼度付きの擬似教師として作る。モデル出力や
補完値を実測正解とは呼ばず、教師モデル・補正条件・版・原本対応を記録する。
採用モデルの通常出力と教師軌跡は別に保存し、必要に応じて再生成できるようにする。

学習の概念は、入力系列を `x`、オフライン教師軌跡を `y` として次の形とする。

```text
入力:  x[n-N+1], ..., x[n]      現在までのNレポート
目標:  y[n+h]                  h = 1 または 2
推論:  f(x[n-N+1:n]) -> 平滑化した将来位置
```

教師 `y` の生成には未来を使える。実時間モデルの入力特徴量・正規化・前処理は現在までに
得られる情報だけで計算し、offline評価でも同じ条件にする。現在時刻の平滑化出力を併設するか、
`h=1/2` を別出力にするかは、モデル選定後の実験で決める。
学習・評価は録画session等の単位で先に分割し、重なるwindowを両方へ混ぜない。

## 時間と系列の扱い

- 初期モデルはレポート順序を使う。細かな実測 `delta-t` を入力することや、厳密な
  時間モデルの導入を試作の前提にしない。必要性が実験で確認された場合に検討する。
- 学習時と実運用のレポート周期を大きく違えない。同じsourceの再送は新しい観測として
  数えず、長い停止、人物の消失・再取得・切替、座標系・stream・continuityの変更で系列を切る。
- 記録済み時刻・sequence・欠落情報は保存する。モデル入力に必須でなくても、後から
  データを選別し、処理遅延を計測し、周期依存を調べる用途がある。
- 過去の履歴保持と、未処理入力の待ち行列は分ける。latest-frame-winsを維持し、
  全レポート処理や未来待ちを優先して古い入力を溜めない。

## 既存録画から始める範囲

`outputs/records/` の9シーン×3カメラ（各約20秒、1280×960、約59fps）を、
姿勢モデルの一次比較と、選定後の時系列方式の成立確認に利用できる候補とする。
静止・Tポーズ・ski姿勢・前屈・屈伸・歩行・dash・kickが主な動作で、椅子遮蔽も含む。
収録周期が大きく異なる旧動画は、そのまま同じ1ステップとして混ぜない。

既存録画のフレーム間隔が完全に復元できないことを、今回のレポート単位の初期検証を
止める理由にはしない。一方、この資料は録画の厳密なカメラ間同期を保証しない。
3D化の品質と実運用遅延はそれぞれ確認し、学習に十分な量・動作の多様性があるかは
実験結果を見て判断する。追加収録や常駐コーパスの蓄積を待たずに一次比較を始められる。

## 選定後に検討する内容

1. 採用姿勢モデルから、同じtopology・座標系の3D入力系列とオフライン教師を用意する。
   raw / 既存filter後のどの段を入力にするか、足部を含む関節範囲、正規化を決める。
2. 固定レポート周期・短い履歴・`h=1/2` で軽量モデルを試す。学習データと評価用sessionを
   分離し、未来情報が推論入力へ混入しないことを確認する。
3. 現行filter、予測なしで現在値を使う基準、単純なレポート差分予測と比較する。
   静止jitter、動作追従、開始・停止・方向転換時の行き過ぎ、未来の教師位置との差を測る。
   擬似教師との一致度だけを絶対精度と呼ばず、平滑化で急動作が失われていないかも確認する。
4. Jetsonでの推論時間・前後処理・出力までの追加遅延と負荷を測り、VRでの動作確認を行う。
   推論が短期予測の効果を食い潰さないかを判断し、採用/保留と切り戻しを決める。

モデル構造・履歴長・実装先・置換するfilter・数値合格しきい値は未決定。
fitra-cam内への配置か外部consumer側への配置かも、選定後に責務と遅延を確認して決める。
実装へ進む時点で `docs/design/` に設計を起こし、関連するtrackと検証戦略を更新する。

## 既存契約・関連Issueとの境界

- [#60: 観測由来・欠損予測・保持・復帰](https://github.com/1hira-c/fitra-cam/issues/60) は
  freshnessと欠損の時間契約を扱う。本案で厳密な `delta-t` をモデル入力に必須としないことは、
  その契約やsource時刻を廃止する判断ではない。予測・平滑化結果は派生値として扱い、
  raw観測や `Fresh` 判定を上書きしない。
- [#62: 2D時系列観測品質](https://github.com/1hira-c/fitra-cam/issues/62) は三角測量前の
  遮蔽対策。本案の主対象は3D化後の平滑化・短期予測であり、その実装を開始条件にしない。
- [FusionPoseの観測/派生値分離](../design/pose-3d-fusion-pose-v1.md) と既存クライアントの
  公開契約は維持する。新しい実行時依存・API・導入先の決定は今回の文書化には含めない。

## 初期案として採らないもの

- 1〜2レポートの未来実測を待つ固定遅延平滑化: 推論時の低遅延要件に合わない。
- 長期の未来予測・遮蔽復元を主目標にする案: 今回の短い予測幅から範囲が広がる。
- 全フレームの手動正解ラベル作成: 大型モデルとオフライン補正で教師を作る方針を優先する。
- 精密な実時間間隔を要求して試作を延期する案: 初期評価は同程度の周期のレポート列で始める。
